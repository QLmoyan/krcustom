# KrCustom 产品简报

## 1. 产品名称

KrCustom

## 2. 韩国品牌名称

커스텀코리아

## 3. 产品定位

面向韩国用户的综合定制服务交易平台。平台连接有定制需求的用户与提供定制服务的商家，核心交易对象是定制 **Service**，而非传统库存商品。

## 4. 目标用户

- 需要个性化定制服务的韩国个人用户
- 有定制需求的小型团队、社团、活动组织者
- 希望找到可靠定制商家并完成需求确认、报价、制作与交付的用户

## 5. 商家类型

- 印刷 / 热转印 / 刺绣等服饰定制店铺
- 礼品、纪念品、周边定制商家
- 包装、贴纸、海报等设计制作商家
- 接受用户自带物品进行二次加工的定制作坊
- 其他提供按需定制服务的本地商家

## 6. 平台与普通电商的区别

| 普通电商 | KrCustom |
| --- | --- |
| 核心实体是 Product（库存商品） | 核心实体是 Service（定制服务） |
| 规格固定，下单即购 | 常需沟通需求、确认效果图、接受报价后再交易 |
| 卖家可发货的现成商品 | 卖家按需求制作或在用户物品上加工 |
| 流程以「浏览 → 加购 → 支付 → 发货」为主 | 流程包含聊天、效果图确认、报价确认、自带物品寄送与制作进度 |

## 7. 核心业务模式

- 平台连接有定制需求的用户与提供定制服务的商家
- 商家发布的是 Service，不是传统库存商品
- 用户可以直接购买，也可以先沟通、确认需求、查看效果图、接受报价后购买

## 8. 三种交易方式

### A. 固定价格直接购买

- 用户选择规格
- 上传设计图片或文件
- 在线下单
- 商家制作
- 商家发货

### B. 沟通询价定制

- 用户联系商家
- 发送文字、图片和文件
- 商家确认需求
- 商家发送效果图
- 用户确认效果图
- 商家发送报价
- 用户确认并付款
- 商家开始制作
- 商家发货

### C. 用户自带物品定制

例如用户把自己的白色衣服寄给商家印图案：

- 用户联系商家并发送物品照片
- 商家确认材质和可制作性
- 商家发送效果图
- 用户确认效果图
- 商家发送报价
- 用户确认并付款
- 用户寄出自己的物品
- 用户包裹内放入姓名、手机号，最好附订单号
- 商家通过订单号、姓名、手机号、物流信息和物品内容交叉确认
- 商家确认收货并拍摄开箱及物品状态照片
- 商家为每件物品生成独立物品编号
- 商家打印物品标签并挂在物品上
- 商家开始制作
- 商家上传制作进度
- 商家完成后寄回用户
- 用户确认收货并评价

## 9. 核心业务流程

平台不得简化或绕过以下关键环节（按业务需要组合使用）：

1. 用户与商家聊天
2. 图片和文件发送
3. 商家发送效果图
4. 用户确认效果图
5. 商家发送报价
6. 用户确认报价并付款
7. 用户自有物品寄送
8. 商家确认收货
9. 制作进度更新
10. 商家返还物品 / 发货
11. 用户确认收货并评价

## 10. MVP 第一阶段范围

第一阶段只包括：

- 首页静态页面
- 服务分类
- 服务卡片
- 服务详情页
- 商家店铺页
- 聊天页面静态原型
- 效果图确认原型
- 报价单原型
- 用户自带物品订单时间线
- 商家后台静态原型

## 11. 暂不开发的功能

第一阶段暂不包括：

- 真实数据库
- 真实登录
- 真实支付
- 真实物流接口
- 实时聊天服务器
- PSD 在线预览
- 自动生成效果图
- 正式管理员后台

## 12. 关键产品原则

1. **Service 优先**：产品建模、页面信息架构和术语都以 Service 为中心，不以库存商品思维设计平台。
2. **沟通可交易**：聊天、效果图与报价是核心交易路径的一部分，不是附属功能。
3. **三种模式并存**：固定价购买、询价定制、自带物品定制可存在于同一 Service，流程不可擅自删减。
4. **韩文前台、中文协作**：前台用户可见文案使用自然韩文；产品文档与团队沟通使用中文；代码标识使用英文。
5. **本地化体验**：金额、日期、手机号按韩国常见格式展示。
6. **文案可国际化**：韩文文案集中管理，第一版只正式开放韩文，但结构预留多语言能力。
7. **MVP 聚焦静态原型**：当前阶段以页面与流程原型验证为主，不自行接入数据库、支付、物流或实时聊天服务。
8. **保护核心流程**：不得为了简化实现而删除聊天、效果图确认、报价确认、自带物品寄送与返还等关键路径。
